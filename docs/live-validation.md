# Live validation and limitations

A single diagnostic integration check passed on 14 October 2026 with Minecraft 26.1.2, Fabric 0.19.5, Fabric API, Minescript 5.0, Sodium and the scoped world-entry helper. PresentMon used the pinned 2.6.0 Windows console binary. This does not establish mod performance gains or compatibility across other computers or versions.

The automated workflow opened the configured profile and disposable RestWorld copy, handled its specific experimental-world prompt without making another backup, prepared and confirmed the correct game session, completed one full unscored route, captured one recorded route, verified scene evidence and saved/quit normally. The route visited the mob, painting and redstone display rooms, with physical walking, two sprint-jumps and camera checks. Redstone display presence is checked; active redstone simulation performance is not covered by this route.

The recorded pass ran unfocused throughout: 469 process/focus samples retained the original client identity. Before and after game-state snapshots showed `WINDOW_ICONIFIED`, an unpaused world and Minecraft's 10 FPS minimized limit. PresentMon retained 1,155 actual frame records over approximately 117 seconds. Frame identity, timestamps, file hash, complete route coverage and capture shutdown passed. All three scene windows passed analysis; normal benchmark scoring refused the diagnostic batch. Raw evidence and the explicitly labeled diagnostic analysis remain in the operator's local output directory.

Preparation began in the foreground and the client later became minimized. This proves a complete recorded route in the minimized state; it does not prove an entire cold-launch preparation and both passes while continuously minimized. Launch can focus the game window, and automatic desktop minimization is not implemented. The operator still approves administrator access for the capture broker and minimizes the correct game window when needed. There are no background-app or power/charging checks.

Earlier attempts exposed three issues: minimized bridge calls exceeded the normal five-minute startup limit; the original corner correction exceeded its short deadline; tiny correction pulses could not cover normal early braking distance. Diagnostic startup now has a fixed ten-minute limit, cancellation is checked between loaded-mod calls, and diagnostic corner corrections use bounded adaptive sneak pulses with movement released before observations. Normal startup remains five minutes and normal foreground movement control is unchanged. The final endpoint tolerance remains 0.2 blocks.

For actual mod comparisons, use normal foreground sessions with matching graphics, heap, display and externally managed conditions. Retain grouped repeats, full unscored passes, confirmation blocks and return-to-control drift checks. Diagnostic throttled FPS must never be substituted for comparison measurements. Continuous resource monitoring was disabled in this integration check and remains separate coverage.

Still unverified: a fresh installation by another user; normal automatic three/five-repeat comparison batches; a complete launch-to-exit run continuously minimized; automated mod switching; and targeted workloads beyond these display rooms. Minimized preparation can be much slower than foreground work, so this diagnostic run does not validate a five-minute screen duration.
